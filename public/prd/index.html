Configurable Lead Form

One phone-verified lead form that marketing can place, style and tune per landing page, on desktop and mobile, without engineering work.

Why

University landing pages need one lead form that marketing can set up per page (where it sits, how it looks, how urgent it feels) without engineering work, and that verifies phone numbers so sales only gets real leads.

02

Where the form appears

One form, several placements. A page can use the banner (inline in the hero), an overlay, or both. They share one state, so anything typed in one shows up in the other.

Desktop and mobile are set up separately. Each page picks one desktop overlay and one mobile overlay (e.g. popup with side image on desktop + bottom drawer on mobile). Screens narrower than 760px count as mobile.

Desktop Banner and overlays

Mobile Banner and overlays

Rules for both

  • Promo images show only on the form; success and exit screens are plain cards.
  • The overlay opens per the configured trigger (on load, after a delay, after a scroll depth, or only on CTA click), and Download Brochure / Apply Now buttons on the page always open it.
03

How the form behaves

Phone first. Everything else unlocks after the OTP is verified, then the journey splits for new and existing leads.

Step 1 · Verify the phone everyone

After a correct OTP we check whether this number is already a lead. That decides which journey follows.

Step 2a · New lead first time on any of our forms

Step 2b · Existing lead number already in our system

Rules

  1. Phone first. Name, email, qualification and course are locked (greyed, 🔒) until the phone is verified. Tapping a locked field sends the user back to the phone/OTP step.
  2. OTP is sent as soon as a valid 10-digit Indian mobile (starts 6–9) is entered. 4 big boxes, auto-advance, paste supported, resend after 30s, Edit to change the number.
  3. New vs existing lead. After verification we look the number up. New → empty fields; existing → pre-fill what we know (still editable) and update the existing lead on submit.
  4. Validation shows when the user leaves a field they've typed in (Enter Valid Name, Enter Valid Email Id). Untouched empty fields never show errors.
  5. Sign Up stays grey until every field is valid and the phone is verified.
  6. Success: "Thank you, {first name}!" with phone, course and a 3-step "What happens next". Two versions: Proceed with My Application (button) or A counsellor will call you (no button).
  7. The urgency element is display only; it never blocks submission.

Lead capture when details reach the CRM

We don't wait for Sign Up. A lead is created as soon as the phone is verified and then updated, so partly filled forms are not lost. All three calls update the same lead (matched by lead_id / phone); nothing is duplicated.

  1. 1
    Phone verified

    Correct OTP entered.

    Sends phone + page context (university, program, form, device, placement, UTMs). Existing leads reuse their record.
    phone_verified
  2. 2
    Form closed early

    Banner ✕, or overlay ✕ / click outside / Esc, before submitting (incl. "No Thanks, Close").

    Sends every field filled up to that point: name, email, qualification, course.
    partial
  3. 3
    Sign Up clicked always

    The user submits the form.

    Sends all fields. This is the confirmed lead.
    submitted
  • Nothing is sent before the phone is verified; no lead without a verified number.
  • Step 2 sends only fields that have a value. Invalid values (e.g. a half-typed email) are sent as typed but flagged invalid.
  • Step 2 can happen more than once (close → reopen → close); each sends the latest values.
  • Step 3 must succeed: if submit fails, show an error and keep the form open with Retry.
  • A submitted lead is never downgraded to partial by a later close.

04

Exit intent

Shown only when someone tries to close the form before submitting, on both the banner form and overlays, every time they try.

FormHow it's closedWhere the exit screen appears
Banner✕ in the card's top-right cornerInside the banner card, replacing the form
Overlay✕, clicking outside, or EscInside the popup / sidebar / drawer

Nothing else triggers it: no cursor-leave detection, no back-button or tab tracking.

Banner form

Overlays

Rules

  • No ✕ on the exit screen; clicking outside or pressing Esc does nothing. Only Continue to Get a Call back or No Thanks, Close leave it.
  • If the visitor has started, show progress: "Your details · 2 of 5 done".
  • Never shown after a successful submit; closing the success screen just closes.
  • Banner closed ("No Thanks, Close"): the banner card is hidden. Download Brochure / Apply Now bring the form back (the overlay if one is configured, otherwise the banner reappears).
  • The banner ✕ can be turned off in the config; then the banner can't be closed and never shows exit intent.

Tracking events

Every event is pushed to the analytics layer (GTM dataLayer → GA4 / Mixpanel) as { event: "form_…", …parameters }. Names are snake_case and start with form_.

Privacy rule: never send phone number, name or email in any event. Join with the CRM using lead_id.
